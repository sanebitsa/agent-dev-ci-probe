# Product Requirements Document (PRD)

**Status: TEMPLATE. Not project-approved or ready for implementation.**

## Purpose

The authoritative description of **what the project must achieve**: user outcomes, requirements, acceptance criteria, constraints, and explicit exclusions. Populate and obtain product-owner approval before initiating implementation.

## Required content when initializing a project

- Product overview, problem, desired outcome, and users.
- User stories and testable functional and non-functional requirements.
- Constraints, architecture boundaries (with details in `docs/ARCHITECTURE.md`), and risks.
- Success criteria, acceptance tests, and release conditions.
- Explicit exclusions and non-goals.
- Decisions, permissions, live-environment validation, or release steps requiring a **HUMAN** gate.

## Rules

- This file starts instructional and intentionally contains **no invented product requirements**.
- Agents may draft requirements for approval, but may not unilaterally approve scope or invent missing decisions.
- Use stable requirement identifiers for traceability from `docs/KANBAN.md` and GitHub Issues.
- Scope changes require product-owner approval and corresponding backlog updates.
- A file's existence does not mean the PRD is approved; only recorded project-specific approval does.
